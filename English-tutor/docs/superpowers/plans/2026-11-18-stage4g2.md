## 1. Scope

Delivered exactly the approved scope:

- New service `english_tutor/services/grammar_feedback.py` — LLM-only grammar
  analysis of the Whisper transcript, with Pattern Bank context.
- Integration into `lesson_voice_task` (`english_tutor/handlers/lessons.py`).
- No new database tables, no schema or migration changes.
- No rule-based fallback: if the LLM is unavailable, the answer is not analysed.

Out of scope (unchanged): Error Journal, grammar SRS cards, persistence of
corrections (Stage 4G.3), scheduler changes, pronunciation scoring.

## 2. Public contract — `analyze_grammar()`

```python
await analyze_grammar(
    transcript,            # Whisper text
    llm,                   # object with chat_json_async() or chat_json()
    *,
    task_description=None, # the speaking prompt from the lesson
    student_level=None,    # CEFR level used to filter patterns
    pattern_ids=None,      # pattern IDs relevant to the lesson
) -> dict
```

Returned keys: `status`, `overall_message`, `corrections`, `correct_patterns`,
`natural_version`, `naturalness_note_ru`, `transcript`.

| status | meaning |
|---|---|
| `analyzed` | LLM returned a usable analysis |
| `llm_error` | call failed, payload was not a dict, or status was unknown |
| `insufficient_context` | transcript empty, or fewer than `MIN_TRANSCRIPT_WORDS` (3) |
| `unavailable` | no LLM service was supplied |

Design guarantees:

- The function never raises for LLM problems; failures are reported via `status`.
- `transcript` is always echoed back so the caller can keep it.
- Defensive parsing: non-dict corrections are dropped, empty/identical
  `original`/`corrected` pairs are dropped, `confidence` is clamped to `0..1` or
  nulled, unknown `pattern_id` values become `null`, at most 5 corrections kept.
- `natural_version` equal to the transcript is dropped.
- An unknown status from the model is treated as `llm_error`, so the bot never
  claims an answer was correct when it was not analysed.

`format_feedback()` renders the result as Russian Telegram text and returns
`None` for an empty result.

## 3. Quota model

`english_tutor/services/limits.py` already provides `try_reserve_llm()` — an
atomic `BEGIN IMMEDIATE` check-and-increment with a hard stop at
`DAILY_LLM_LIMIT = 200`.

- `lesson_voice_task` now reserves **one unit per real LLM call** instead of the
  previous `can_use_llm()` + `register_llm_call()` pair (which was a TOCTOU
  check-then-increment).
- Unit 1 is reserved before `save_and_transcribe()`. `save_and_transcribe()`
  itself never touches `daily_usage`, so the handler is the single place that
  charges for Whisper.
- Unit 2 is reserved only when the analysis will actually reach the LLM, i.e.
  `len(transcript.split()) >= MIN_TRANSCRIPT_WORDS`. A too-short answer produces
  a local Russian message and costs nothing extra.
- If unit 2 cannot be reserved, the feedback is skipped silently and the task
  still completes. Quota exhaustion never blocks finishing the task.

## 4. Failure behaviour in the handler

| Situation | User sees | Lesson session |
|---|---|---|
| no voice in message | "Жду голосовое" + task | preserved |
| voice too long | limit message | preserved |
| daily quota exhausted (Whisper) | "Дневной лимит запросов исчерпан." | preserved |
| Whisper error | "Не удалось распознать. Попробуй ещё раз." | preserved (retry allowed) |
| empty transcript | "Не расслышал 🎤" | preserved (retry allowed) |
| analysis ok | transcript, "🧠 Грамматический разбор:", corrections | completed |
| analysis failed (`llm_error` / `unavailable`) | transcript, "⚠️ Разбор грамматики сейчас недоступен. Расшифровка сохранена." | completed |
| transcript too short | transcript, "Ответ слишком короткий для разбора…" | completed |
| analysis quota gone | transcript, no feedback | completed |

## 5. Pattern Bank repair

The Pattern Bank file on disk (`english_tutor/services/patterns.py`) was not valid
Python: it contained `//` comment lines, duplicated `pat_00x` blocks and a
truncated dictionary, so any import of it raised `SyntaxError`. The previous
`grammar_feedback.py` on disk was a partial draft with the docstring in the middle
of the file. Both files were rebuilt from the approved Stage 4G.1 content:

- `patterns.py`: 10 grammar patterns (`pat_001`–`pat_010`) and 9 functional
  templates (`tpl_001`–`tpl_008`, `tpl_008b`) with the fields documented in
  `2026-11-17-stage4g1.md`, plus `ALL_PATTERNS`, `get_pattern()`,
  `list_patterns()` (accepts `ce_level` or `cefr_level`), `normalize_pattern_id()`
  (alias-aware, returns `None` for unknown input) and `build_patterns_prompt()`
  (filters by CEFR level, skips unknown IDs).

### Cleanup pass on top of the feature

- **Fixed `/resume` double restore** (`english_tutor/handlers/lessons.py`):
  `resume_cmd` awaited `stories.resume_cmd()` at two places and repeated the
  whole guard/lesson-restore block, so a story-only session was restored twice.
  The duplicated block was removed; the function is now a single linear flow
  (guard → both/none → lesson restore → story delegation).
  Covered by `tests/test_resume_cmd.py` (5 tests), which asserts the story
  handler is called **exactly once** and not called for the other branches.
- **Fixed `NameError` in `mat:ex:done`** (`english_tutor/handlers/materials.py`):
  the completion message used a local `queue` variable that only existed in the
  sibling branch, so finishing material exercises crashed after
  `state.clear()` and the student never saw the score. It now reads the total
  from `data["exercise_queue"]`. Covered by
  `tests/test_stage4c.py::test_material_exercise_done_reports_total`.
- **Removed duplicated bookkeeping** in the lesson-completion path
  (`meta` / `find_lesson_id` were computed twice, `delete_lesson_session` ran on
  an already deleted session) and a redundant second `conn.commit()` in
  `db.delete_lesson_session`.
- **Formatting debt**: all `E501` / `E402` findings fixed across
  `handlers/{lessons,materials,review}.py`, `db.py` and the affected tests.

   flow remain unverified in this environment.

   `instruction_ru` fallback in `format_lesson()` are prior-stage changes that
