## 2. Публичный контракт — `analyze_grammar()`

```python
await analyze_grammar(
    transcript,            # текст из Whisper
    llm,                   # объект с chat_json_async() или chat_json()
    *,
    task_description=None, # формулировка задания на говорение
    student_level=None,    # уровень CEFR для фильтрации паттернов
    pattern_ids=None,      # ID паттернов, относящихся к уроку
) -> dict
```

Возвращаемые ключи: `status`, `overall_message`, `corrections`,
`correct_patterns`, `natural_version`, `naturalness_note_ru`, `transcript`.

| status | значение |
|---|---|
| `analyzed` | LLM вернула пригодный для показа разбор |
| `llm_error` | вызов упал, ответ не словарь или status неизвестен |
| `insufficient_context` | расшифровка пустая или короче `MIN_TRANSCRIPT_WORDS` (3 слова) |
| `unavailable` | сервис LLM не передан |

Гарантии реализации:

- Функция не выбрасывает исключений из-за проблем с LLM — сбой передаётся через `status`.
- `transcript` всегда возвращается обратно, чтобы вызывающий код мог его показать.
- Защитный разбор ответа: отбрасываются не-словари в `corrections`, пустые
  пары `original`/`corrected` и пары, где они совпадают, `confidence`
  ограничивается диапазоном `0..1` или обнуляется, неизвестные `pattern_id`
  становятся `null`, остаётся не более 5 исправлений.
- `natural_version`, совпадающий с расшифровкой, отбрасывается.
- Неизвестный `status` от модели трактуется как `llm_error`, поэтому бот никогда
  не утверждает, что ответ разобран и верен, если разбора не было.

`format_feedback()` рендерит результат в русский текст для Telegram и возвращает
`None`, если показывать нечего.

## 3. Модель квот

В `english_tutor/services/limits.py` уже есть `try_reserve_llm()` — атомарная
проверка-с-инкрементом через `BEGIN IMMEDIATE` с жёстким лимитом
`DAILY_LLM_LIMIT = 200`.

- `lesson_voice_task` теперь резервирует **одну единицу на каждый реальный вызов
  LLM** вместо прежней пары `can_use_llm()` + `register_llm_call()` (это была
  проверка-и-затем-инкремент, уязвимая к гонке, TOCTOU).
- Первая единица резервируется до `save_and_transcribe()`. Сам
  `save_and_transcribe()` никогда не трогает `daily_usage`, поэтому обработчик —
  единственное место, где списывается квота за Whisper.
- Вторая единица резервируется только если разбор действительно пойдёт в LLM,
  то есть при `len(transcript.split()) >= MIN_TRANSCRIPT_WORDS`. Слишком короткий
  ответ даёт локальное русское сообщение и не стоит дополнительной квоты.
- Если вторую единицу зарезервировать не удалось, разбор молча пропускается, а
  задание всё равно завершается. Исчерпанная квота никогда не блокирует
  завершение задания.

## 4. Поведение при сбоях в обработчике

| Ситуация | Что видит пользователь | Сессия урока |
|---|---|---|
| в сообщении нет голосового | «Жду голосовое» + задание | сохраняется |
| голосовое слишком длинное | сообщение о лимите | сохраняется |
| дневная квота исчерпана (Whisper) | «Дневной лимит запросов исчерпан.» | сохраняется |
| ошибка Whisper | «Не удалось распознать. Попробуй ещё раз.» | сохраняется (можно повторить) |
| пустая расшифровка | «Не расслышал 🎤» | сохраняется (можно повторить) |
| разбор успешен | расшифровка, «🧠 Грамматический разбор:», исправления | завершается |
| разбор не удался (`llm_error` / `unavailable`) | расшифровка, «⚠️ Разбор грамматики сейчас недоступен. Расшифровка сохранена.» | завершается |
| расшифровка слишком короткая | расшифровка, «Ответ слишком короткий для разбора…» | завершается |
| квота на разбор закончилась | расшифровка, без разбора | завершается |

## 5. Починка Pattern Bank

Файл Pattern Bank на диске (`english_tutor/services/patterns.py`) не был
корректным Python: в нём были строки-комментарии `//`, продублированные блоки
`pat_00x` и оборванный словарь, поэтому любой импорт давал `SyntaxError`.
Прежний `grammar_feedback.py` на диске был частичным черновиком с docstring в
середине файла. Оба файла пересобраны по согласованному содержимому этапа 4G.1:

- `patterns.py`: 10 грамматических паттернов (`pat_001`–`pat_010`) и 9
  функциональных шаблонов (`tpl_001`–`tpl_008`, `tpl_008b`) с полями,
  описанными в `2026-11-17-stage4g1.md`, а также `ALL_PATTERNS`, `get_pattern()`,
  `list_patterns()` (принимает `ce_level` или `cefr_level`), `normalize_pattern_id()`
  (понимает алиасы, возвращает `None` для неизвестного входа) и
  `build_patterns_prompt()` (фильтрует по уровню CEFR, пропускает неизвестные ID).

  (`english_tutor/handlers/lessons.py`): `resume_cmd` дважды вызывал
